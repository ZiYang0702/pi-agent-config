# 全局规则

## 做到一半要我拍板

我没看过你刚读的代码、日志和页面，只凭这段话做决定，所以这里不求短。纯文字提问和 AskUserQuestion 都写这五项，每项一两句：

1. 问题：出了什么情况，要我定什么。
2. 来由：做到哪一步、发现了什么、开工时的安排为什么管不了它。
3. 和目标的关系：卡在这次目标的哪一块。怎么选都不影响目标、以后也好改的，不问我，自己定，收尾时说一声。
4. 选项：每个选完后交出来的东西是什么样，具体到我能看到、用到的差别。附代价：多花多少工夫、哪部分返工、以后好不好改。
5. 建议选哪个，为什么。

写法：
- 票号、条目号后面跟一句它是什么。
- 直接说事情本身，不用自起的名字和比喻。
- 路径条数、百分比、git 条件这类技术细节，翻成对最终结果的影响再写；原始数据放文件给路径。
- 涉及界面、布局、流程、结构，主动附字符画或表格，把各选项并排摆出来。
- 用 AskUserQuestion 时，五项写在调用前的正文；问题栏只放第 1 项；选项 description 写选了的结果，不复述选项名；示意图放 preview。一次问几件事，每件分开写五项。

## 二、干活

### 交不交给子 Agent

按顺序问，遇到第一个「自己做」就停：
1. 过程产出多、结论只要几行？不是 → 自己做。
2. 中途要和我来回确认？是 → 自己做，子 Agent 没法半路问我。
3. 主会话下一步判断要靠这些细节？是 → 自己做。
4. 改动很小？是 → 直接做。

都过了才派，只带结论回来。典型的活：找代码、读大文件、跑测试看日志、查文档、调研。

派之前读 `~/.pi/docs/子Agent.md`：怎么拆、任务说明写什么、交回怎么核实。

### 主会话和子 Agent 都照做

- 跑测试套 `quiet-test`，如 `quiet-test python3 -m pytest tests/`。它只打汇总行和失败断言行，全量输出在它最后一行给的路径里，要细看就 grep 那个文件。
- 脚本只打一行汇总，明细写文件。
- 看代码先 grep 定位，只读相关行段；同一文件不整读第二遍。页图只看点名的那几张。

### 做票

票上进度只由主会话写。开票做、写票评论之前读 `~/.pi/docs/做票.md`。

### 上下文到 15 万

还没收尾就停，先把进度写下来（做票就写到票上），剩下的开新会话做。非要在本会话继续，也先写进度，再 `/compact` 加一句接下来做什么。
