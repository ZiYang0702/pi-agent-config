# 调用子 Agent

## 1. 定范围、选角色

用文件名或少量搜索命中定位；能列出问题和完成条件即停止。每批一个明确终点，预计超过 20 轮则按模块、步骤、审查角度或页组拆分。

按任务选角色：scout 找证据，planner 制定计划，reviewer 只读审查，worker 实施与运行验证。

## 2. 写任务

子 Agent 不继承主会话对话。每项任务写全目标、范围、完成条件、期望产出、工作目录、必要背景、已核实结论、适用约束及全局共用规则；涉及写入时注明允许修改的文件和是否授权提交。

给 worker 创建临时目录并提供独立的绝对笔记路径。只读角色的检查点由主会话在交回后保存。

接力只传已核实进度、必要票号/链接、笔记路径和下一入口；旧笔记标为未核实草稿，要求核对当前文件状态，不传整段历史或日志。

## 3. 调用

使用 `subagent`，参数按工具定义：

- 单任务或需要中途核实、确认、接力：分开调用。
- 并行：仅派互不依赖的批次；共享工作目录时，写入范围必须互不重叠，审查等待相关写入结束。
- 链式：仅用于无需中间核实的步骤。每步任务独立完整；`{previous}` 是前项输出，未必已核实。正文的「未完成」「阻塞」不会自动中断链。

默认使用用户级角色；仅在需要且信任项目角色时启用 `both` 或 `project`。

## 4. 核实与接力

按完成条件核实：提交查 git log/show；改动查对应范围的 git diff --stat；测试用 quiet-test 独立运行；只读结论抽查关键证据，细审可另派 reviewer。

保存检查点并标明已核实部分。未完成则缩小剩余范围，另起调用以新上下文接力；待用户决定的阻塞交回用户。每项完成条件均有证据才算完成。

主会话核实后更新票；同一阶段接力编辑同一条进度评论。报告与事实不符时按实际记录并告知用户。
